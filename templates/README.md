# Templates

Four starting templates, in two formats each.

| File | Use it when |
|---|---|
| `resume-base.md` | Default. One page. Most applications. |
| `resume-expanded.md` | Two pages. Senior roles, 10+ years, technical roles wanting depth, or academic/government applications that expect detail. |
| `cover-letter-base.md` | Default. ~300 words. Most applications. |
| `cover-letter-expanded.md` | ~450 words. Career changes, roles where you need to explain a gap or a pivot, or postings that ask for specific written responses. |

## Placeholders

Anything in `{{DOUBLE BRACES}}` gets replaced. Anything in an HTML comment is guidance for you and the agent — it disappears when the document is rendered.

Repeatable blocks are marked `<!-- REPEAT -->` … `<!-- /REPEAT -->`. Duplicate the block per role, per project, per whatever.

## Using your own template instead

These are deliberately plain so that everyone using this system doesn't hand the same-looking document to the same recruiter. If you want something with more personality, or your industry has a house style, bring your own:

1. Find a resume or cover letter format you like — a PDF, a Word doc, a screenshot, a link, or just a description.
2. Put it in `_inbox/` (or paste it into the chat).
3. Tell the agent: *"Use this as my template format instead of the default."*

The agent will read the structure — section order, headings, how experience is presented, tone, length — and rebuild it as a template file here. Your content still comes from your atoms; only the shape changes.

**Two things to watch for.** Don't copy someone's actual wording or accomplishments, only their structure. And if the format you like uses columns, tables, sidebars, icons, or graphics, tell the agent — those look good to humans and parse badly in applicant tracking systems, and it will offer you a plain version to submit alongside the pretty one.

## Formatting rules these follow

No tables, no columns, no text boxes, no headers or footers, no graphics, no icons. Standard section headings. Dates in a consistent format. This is what survives an ATS parse intact. Keep it that way unless you have a reason not to.
